# Conformance results contract (platform runners ⇄ report)

This file documents the interface between the fixture generator
(`jui conformance generate`, plan 01) and the per-platform conformance
runners (web / iOS / Android — plans 02/03/04). It is hand-maintained;
everything else in this directory except `results/` is `@generated`.

## Directory layout

```
conformance/
├── fixtures/<Section>/<attr>__<case>.layout.json   # @generated Layout JSON
├── fixtures/<Section>/<attr>__<case>.test.json     # @generated screen test (jsonui-test-runner schema)
├── manifest.json                                   # @generated fixture list + classification
├── results/<platform>.results.json                 # written by each platform runner
├── baselines/<env>/<platform>.hashes.json          # @generated by `jui conformance baseline update` (env: local / ci)
├── baselines/README.md                             # hash algorithm + threshold + environment-key rationale (hand-maintained)
├── artifacts/<platform>/*.png                      # local / CI artifact only — never committed
├── INTERACTIVE_HOST_CONTRACT.md                    # conformanceState host contract (hand-maintained)
├── RESULTS_SCHEMA.md                               # this file (hand-maintained)
└── REPORT.md                                       # @generated by `jui conformance report`
```

`<Section>` is the top-level key of `shared/core/attribute_definitions.json`
(`common`, `Label`, `Button`, ...). `common` attributes are hosted on a `View`
target (or `Button` for interaction attributes — see `manifest.fixtures[].host`).

All paths inside `manifest.json` and inside each test's `source.layout` are
**relative to the `conformance/` directory**.

## Fixture conventions (what a runner must provide)

- Every layout has a root `View` with `id: "root"` and the component under
  test with `id: "target"`. View-reference fixtures add a sibling
  `id: "anchor"`.
- Host apps MUST bundle an image asset named **`conformance_sample`** —
  image-typed fixtures reference it.
- Tests are plain jsonui-test-runner screen tests (`jsonui-test validate`
  passes with zero warnings). `assertable` fixtures carry assertions;
  `visual` fixtures end in a `screenshot` action whose `name` is
  `<Section>_<attr>__<case>` — save the artifact and record its path in your
  results file.
- `manifest.fixtures[].platforms` ⊆ `["ios", "android", "web"]` (mapped from
  the definition's `swift`/`kotlin`/`react` tags). If your platform is not
  listed, report the fixture as `"skipped"` with
  `detail: "not applicable to <platform>"` — do not drop it silently.
- `manifest.fixtures[].aliasOf` links an alias-spelling fixture to its
  canonical fixture id. Both must produce the same outcome; the report
  flags divergence.
- `class: interactive` fixtures (v2) additionally carry a `state` object —
  the variables + host-injected handlers the fixture needs. Hosts implement
  ONE generic provider for all of them; the full contract is in
  `INTERACTIVE_HOST_CONTRACT.md`. Their tests use only standard runner
  actions (`tap` / `input` / `longPress` / `selectOption`) and assertions.

## `results/<platform>.results.json`

One file per platform, written atomically after a full suite run:

```json
{
  "platform": "web",
  "manifestHash": "<sha256 of conformance/manifest.json at run time>",
  "runner": { "name": "playwright", "version": "1.44.0" },
  "webMarkers": {
    "webFixturesRunnable": 2,
    "webFixturesReachedCapture": 2,
    "alreadySettled": 2,
    "waitedThenSettled": 0,
    "timedOut": 0,
    "markerAbsent": 0
  },
  "results": [
    {
      "id": "Label/text__static",
      "status": "pass",
      "detail": "",
      "screenshot": "artifacts/web/Label_text__static.png"
    }
  ]
}
```

| Field | Required | Meaning |
|---|---|---|
| `platform` | yes | `web` \| `ios` \| `android` (must match the filename stem) |
| `manifestHash` | yes | sha256 hex of the exact `manifest.json` bytes the run used. The report marks results **stale** when it differs from the current manifest |
| `runner.name` / `runner.version` | yes | driver identification (playwright / xcuitest / uiautomator, ...) |
| `results[].id` | yes | fixture id from `manifest.fixtures[].id` |
| `results[].status` | yes | `pass` — all steps green · `fail` — an assertion failed · `error` — could not execute (render crash, missing element, timeout) · `skipped` — intentionally not run (must set `detail` with the reason) |
| `results[].detail` | on non-pass | human-readable failure/skip reason (single line) |
| `results[].screenshot` | optional | artifact path relative to `conformance/` (visual fixtures should always set it) |
| `webMarkers` | per declaration | run-level census of the Web load-marker wait — see below. Required of the platforms named in `gate.EXPECTED_WEB_MARKER_HOSTS`, optional for the rest |

### `webMarkers` — asserting that a Web capture waited for the page to paint

A web view exists the instant it is made, so a screenshot taken mid-load is
blank — and **a blank fixture still differs from its control**, so `control_diff`
calls the attribute active and a baseline re-bake of the same race calls itself
a pass. Both sides of that race sat in committed iOS baselines under a green
gate. **No arm that looks at pixels can separate "waited and painted" from "did
not wait"**, so the host counts the wait and the gate reads the count.

The wait's own failure wears the face of the bug it fixes: when the load marker
is absent the capture proceeds immediately, exactly as before, and the timeout
is never reached. The marker being missing has four causes and only the first
is correct — the fixture has no web view; the env flag did not reach the app;
the linked library predates the marker API (SwiftJsonUI < v10.23.0); the marker
does not surface as an accessibility element (measured once already, when an
identifier set on the `WKWebView` itself produced no element at all).

⚠️ THE FIRST VERSION OF THIS CENSUS COUNTED THE WRONG THING AND CRIED WOLF ON
ITS FIRST REAL RUN. It used sightings of the *pending* marker as the detector
for "this fixture has a web view". Pending is a **transient** state: a local
`loadHTMLString` settles before the runner's first query, so the tree carried
only `sjui_web_loaded`, the census read 0 of 2, and the screenshots were
byte-identical to the baseline. Measured 2026-09-15 by dumping the element tree
at the exact query point — the 1x1 marker was present as a child of the
`WKWebView`, already flipped to loaded, with the page's own text beside it.

So the detector is the **declared** fact — `manifest.host == "Web"`, which is
stable and names the control (`__control/Web`, whose *component* is
`__control`) as well as the attribute fixtures — and the markers are used only
as the wait's terminating condition. Each fixture lands in exactly one bucket,
and each bucket's zero means one thing:

| Key | Meaning |
|---|---|
| `webFixturesRunnable` | informational — Web-hosted fixtures the run intended to execute |
| `webFixturesReachedCapture` | **the denominator**; the four buckets below sum to exactly this |
| `alreadySettled` | the page had painted before the runner looked — correct, and the common case on a fast machine |
| `waitedThenSettled` | pending was found, then loaded arrived within the budget — the wait did its job |
| `timedOut` | pending was found, loaded never arrived — **a notice, not a failure** |
| `markerAbsent` | neither marker ever appeared — **the failure**: the mechanism is gone |

The gate fails on `markerAbsent > 0`, and on buckets that do not sum to
`webFixturesReachedCapture`. A timeout is deliberately not failed: the capture
is still judged by fixture-vs-control, which is readable, and failing here
would make a slow page indistinguishable from a broken marker. The conservation
check exists because a future branch that falls through every bucket would
shrink the population silently, and a judgment with nothing left to judge
passes.

**Who must emit one is declared, not inferred.** `gate.EXPECTED_WEB_MARKER_HOSTS`
names the platforms whose absence of a census fails the gate (today: `ios`,
adopted in SwiftJsonUI's `ConformanceHost` on 2026-09-15). The obvious
alternative — stay quiet until some host reports, then name the ones that do
not — is silent in exactly the failing case: **the run where the census
disappears has no reporting hosts, which is the same state as the run before
anyone implemented it.** Worse, a census removed from the host takes the host's
own `XCTAssert` with it, so host and gate would fall quiet together. With a
declaration, absence is a named refusal:

| | declared | not declared |
|---|---|---|
| **emits a census** | steady state — silent | notice: add it to the declaration |
| **emits nothing** | **fails** — regression or a stale declaration | silent — has not adopted it |

An unreadable census (wrong types) counts as *emitting nothing*, not as
passing: unreadable is "cannot judge", which is neither satisfied nor
not-applicable. Grow the declaration in the same commit that teaches a host to
emit one.

Rules:

- Emit **one entry per manifest fixture** — every fixture id in
  `manifest.fixtures` must appear exactly once (use `skipped` + `detail`
  rather than omitting). Unknown / extra ids are flagged by the report.
- No timestamps or host-specific absolute paths inside the file (results
  are committed; diffs must stay reviewable).
- Encoding: UTF-8, 2-space indent, trailing newline (match the generator).

## `manifest.json` (produced by `jui conformance generate`)

```json
{
  "_generated": { "sentinel": "@generated", "...": "..." },
  "schemaVersion": 2,
  "generatedFrom": "<sha256 of attribute_definitions.json>",
  "counts": { "fixtures": 0, "assertable": 0, "visual": 0, "interactive": 0,
              "skipped": 0, "promoted": { "callback": 0 } },
  "fixtures": [
    {
      "id": "Label/text__static",
      "component": "Label",
      "attribute": "text",
      "case": "static",
      "class": "assertable",
      "host": "Label",
      "writtenKey": "text",
      "aliasOf": null,
      "value": "Conformance Text",
      "platforms": ["ios", "android", "web"],
      "mode": null,
      "deprecated": null,
      "layout": "fixtures/Label/text__static.layout.json",
      "test": "fixtures/Label/text__static.test.json",
      "state": null,
      "promotedFrom": null
    }
  ],
  "skipped": [
    { "component": "Slider", "attribute": "onValueChange", "reason": "callback" }
  ]
}
```

- `class`: `assertable` (assertion-based), `visual` (screenshot only) or
  `interactive` (v2 — binding/callback fixtures; carries a non-null `state`,
  see `INTERACTIVE_HOST_CONTRACT.md`). `untestable` attributes never become
  fixtures — they live in `skipped` with a reason (silent drops are
  forbidden).
- `promotedFrom` (v2): the v1 skip reason (`callback` / `binding-only`) this
  attribute was promoted out of, or `null`. `counts.promoted` aggregates the
  promoted attribute count per reason; the report's *Interactive fixtures*
  section shows promoted vs still-skipped.
- fixture file stems are deduplicated case-insensitively (`_2` suffix), so
  attributes differing only by case (`onclick` / `onClick`) never collide on
  macOS filesystems — always resolve files through `layout` / `test`, never
  by reconstructing the path from the id.
- `mode` / `deprecated` carry the raw values from `attribute_definitions.json`
  (`swiftui` / `uikit` / `compose` / `dynamic-only`, ...). v1 does not encode
  mode in the test `platform`; a runner hosting a different mode may report
  `skipped` with the mode as `detail`.

## `jui conformance baseline update` (v2)

`jui conformance baseline update --platform <p> [--env <e>] --fail-on-moved` hashes
`artifacts/<p>/*.png` into `baselines/<e>/<p>.hashes.json` (perceptual dHash-64;
Pillow required — optional extra `jui-tools[conformance]`). Algorithm,
measured threshold rationale and the update workflow: `baselines/README.md`.
PNGs themselves are never committed.

## `jui conformance report`

Merges `results/*.results.json` against `manifest.json` into `REPORT.md`:
cross-platform mismatch table first, then the interactive-fixture section
(promoted counts + per-platform status), the visual-regression section
(same-platform baseline comparison: compared / regressions / no-baseline /
missing-artifact — screenshots without a baseline hash are reported, never
silently passed), per-platform summary (with stale warnings), the full
fixture × platform matrix, and the skipped-attribute table.
Symbols: ✅ pass · ❌ fail · ⚠️ error · – skipped · blank = no result.
